# 珠宝素材接入：本次样板与后续交付

## 本次实际处理

宝石.zip → 安全提取 19 个 3DM → rhino3dm 8.35.0 读取独立 Mesh → 保留切面顶点与法线 → `(x,y,z) → (x,z,-y)` 转为 Y-up → 三角化 → GLB → Three GLTFLoader 回读 → 拓扑和尺寸检查 → 宝石清单 → 按选择加载。

每个 3DM 同时有 Brep、曲线和独立 Mesh，本次选用已有 Mesh，不把多种表示叠在一起。19 款共 163,572 bytes / 2,482 三角面。圆形 352 个渲染顶点、174 个三角面，与此前用户圆形 GLB 几何逐项一致。

所有导出均无退化面、重复面、边界边或方向冲突，合并精确重合位置做拓扑检查时为单个闭合连通壳。此检查不代表已验证曲面自交或可制造性。源模型有些区域本身带平滑法线，本次保留。

原始单位均为 Rhino `UnitSystem.None`，未擅自当成毫米或标注克拉。GLB extras 和接入清单记录未标定状态。单件预览居中并统一最大平面宽度；成品圆石按目标腰围宽度等比缩放并对齐腰围高度。

转换脚本和原始检查保存在本工作区的 `../research/2026-10-28-gems/`，其中 `inspection.md` 是完整报告，`inspect-and-export.py` 是本次专用转换器。它面向这批已有独立 Mesh 的文件，不是任意 CAD 通用修复器；Brep 没有网格缓存时，应由 Rhino / Blender 提供受控的网格化导出。

## 运行时怎么加载

- `atelierManifest.ts` 维护 19 款 URL 与名称；宝石库一次选择一款，由 GLTFLoader 缓存其源模型。
- 展示几何单独克隆；镶嵌圆石只替换 `CenterDiamond`，不改共享的配石源几何。
- 金属静态 BVH 与局部遮蔽在成品载入时生成；光线和颜色切换更新材质，不重新烘焙几何。
- 实时渲染材质覆盖 GLB 里的中性预览材质。光学效果由运行时光线、折射和环境控制，GLB 本身不携带“钻石效果成品”。
- 生产环境把带版本哈希的 GLB / 图片放对象存储和 CDN，数据库保存资产清单、兼容关系与尺寸元数据。无需把全部款式打成一个大 GLB 或一次下载整个库。

## 交给建模同事的最低规范

1. 保留原 CAD / Blender 工程，明确毫米单位、Y-up 交付轴向、模型原点及腰围/镶口锚点。记录主石实际长宽高、腰围高度、允许切形和尺寸范围。
2. 提供 Web GLB，或提供可稳定转换的 OBJ + MTL / 3DM Mesh。金属、主石、配石、爪座分别命名；实例共享几何，变换不要隐含在不明父节点中。
3. 宝石提供闭合网格、正确朝外面序和切面法线；不要跨切面全局平滑。金属提供真实倒角与合理圆滑法线，检查薄壁、交叠和爪尖穿入。
4. 约定每个镶座与切形的兼容尺寸，给出已装配样板。等比缩放只解决展示比例，不能替代镶口、爪位和生产工程校验。
5. 资产验收记录文件哈希、三角面、材质/纹理数、边界与法线检查、缩略图及版本；Web 优化保留切面边缘。小宝石文件不必为了压缩而破坏精度。

## 后续工具优先级

先做固定导出规范和小批验收脚本，再做一个上传、自动检查、预览、发布资产版本的内部网页。Rhino/Blender 批量导出负责受控网格化；glTF Transform 负责检查和优化，不能把任意 Brep 自动变成正确的珠宝资产。复杂的建模插件等重复交付流程稳定后再投入。

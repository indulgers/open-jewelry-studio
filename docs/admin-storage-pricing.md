# 后台商品与存储

后台分工

- 上传复核负责 OBJ 分区、接合点及生成部件版本，不重复陈列每个部件的预览和下载。
- 部件管理按戒头、戒圈、戒头配钻、戒臂铺钻、接合件筛选，提供部件预览、下载和加价。戒头配钻包含在戒头加价中，接合件包含在戒圈加价中。
- 商品管理负责选择配套部件、基础价、工艺复核、草稿预览、发布、下架及恢复。原款定价用于维护已有参考原款的基础价。

## R2 是运行时文件来源

`studio/v1/stock/library.json` 和 `catalog.json` 保存已有款式及部件目录。`assets.json` 是允许公开访问的模型和图片清单，只有该清单内的文件才能通过 `/models/…`、`/media/…` 取得短期签名地址。原始 OBJ 和模型识别资料放在私有 `stock/sources/`，需后台登录才能下载原始文件。

后台上传仍进入私有 `models/`，草稿在 `drafts/`，发布快照在 `releases/`，当前可见版本由 `published/` 指向。公开文件入口不会暴露上传目录或草稿文件。

正式构建移除 `dist/models` 和 `dist/media`，这些路径统一经过 R2 文件接口。前台先读取 R2 的款式、部件和价格目录，读取失败显示重试，不回退到随代码打包的旧目录。配置了 R2 和管理员密码的本地开发也使用同一套云端接口；无云端配置时保留离线建模工作台。

已有文件的迁移工具为 `scripts/model-admin/migrate-stock.mjs`。从环境变量读取密钥，按内容摘要检查已存在文件，使用条件写入避免覆盖并发修改，最后更新目录。项目内源文件保留作离线备份，不再作为线上文件源。

## 简单报价

报价 = 模板基础价 + 所选戒头加价 + 所选戒圈加价 + 配套戒臂铺钻加价。

价格最多两位小数，加总按分计算。配钻与镶座必须来自相同部件版本。部件价格保存在 R2 的 `pricing.json`，支持版本冲突保护。商品保存草稿时读取当前部件价格并形成快照；发布和购物车都使用这个快照，后续改价不会改变已发布商品或已有购物车方案。重新保存并发布商品才能应用新加价。

已发布组合商品加购前会请求当前有效版本的报价，停售或已被新版本替代时不能继续按旧页面加购。购物车保留价格版本、配置明细和当前 3D 截图。仍为参考报价和浏览器内演示购物车，不涉及付款及库存扣减。

参考原款的基础价和部件加价供新访问的原款编辑器读取；原有宝石外观等简单选项加价保留。原款定价保存后生效，已保存购物车保持原价。

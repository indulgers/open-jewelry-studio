# 真实镶嵌装配：主石、戒冠、配钻和金属连接

本工作台研究 Helzberg 与 Blue Nile 的成品戒托配置逻辑，**不复制商业 CAD 设计**。本页明确可执行设计约束和预览与生产模型的边界。

## 1. 为什么旧版看起来“钻石飘逸”

旧版把已居中的宝石 Mesh 放到金属表面，宝石的**包围盒中心**并非腰棱。宝石亭部很可能与金属发生错误穿透；每颗小钻独立添加双层金属环，使花瓣表面出现不真实的密集银色条纹。

新版从原 GLB 提取近似腰棱，输出坐标的 **Y=0 表示腰棱**。局部空间再由 site 的位置与法线决定镶嵌方向。

## 2. 宝石、镶口、金属实体的分工

| 类型 | 几何 | 不能被替代的条件 |
| --- | --- | --- |
| 主石爪镶 | 主石真实刻面、腰棱座、底部 gallery、4/6 条变形爪、连接戒臂的桥 | 爪顶端接近宝石冠部，底端进入 metal gallery；不能是悬空柱 |
| 主石包镶 | 主石、连续金属包边/嘴、低位下托、连接戒肩 | 包边/支撑位于宝石腰棱，不是孤立的金属圆环 |
| 花瓣微密镶 | 有孔的花瓣承托曲面、石位、可视化珠爪、共用金属片 | 小钻不能每颗都有完整独立大篮托；要保留镶口与边缘金属 |
| 戒肩连排 | 沿圆周曲率定位的宝石，戒肩外表面局部开口 | 配钻不能以完全相同的 Y 高度摆在不同曲率位置 |
| 轨道镶 | 连续两侧金属轨道、对应石位和承托位置 | 不能把多颗小钻套在相互隔离的包镶中，却称为轨道镶 |

## 3. 现在已运行的算法

- `src/stone-first/gemFit.ts`：识别原始钻石 GLB 近似腰棱平面。
- `src/stone-first/recipe.ts`：基于宝石石径、目标腰棱净距和花瓣面积计算交错石位，记录 `leaf/t/u` 语义锚点。
- `src/stone-first/geometry.ts`：花瓣通过带孔 Shape 曲面建模；戒肩局部外层网格留出配钻开口；主石 4/6 爪、金属包边、轨道双边框以及底部连接按位生成。
- `src/stone-first/StoneFirstStage.tsx`：使用项目现有 HDR/光学材质渲染主石；高画质支持小钻的共享 BVH 折射，提供整体、俯视、侧面和近景检查。
- `src/stone-first/StoneFirstStudio.tsx`：保留五步流程，新增戒冠高度、配钻下沉深度和 4/6 爪交互。

## 4. 本轮的真实边界

当前的“金属开孔”是局部参数化可视化切孔：花瓣为双面穿孔曲面加细金属边缘（尚未形成封闭侧壁 B-rep），戒肩为外层三角片开孔，还**不是整个戒圈的 CAD 级实体布尔差**。金属在空间上通过过渡支撑连接，但还没有工厂可接受的单一封闭 B-rep。

完整生产验收需要：CAD 实体精准布尔、所有金属部件并集、水密性和自交检查、镶口壁厚场、爪根截面、石位镶嵌可达性、抛光/铸造余量、库存钻石与镶座适配，以及工厂打样。不能因为 WebGL 通过渲染就称它可以生产。

## 5. 视觉验收

对三种代表作品逐一检查：
1. 四瓣主钻戒：无悬空主石、主石腰棱有支撑，4/6 爪变化有明显可见结构差异，侧视不出现孤立金属柱。
2. 花瓣密镶戒：花瓣小钻不是过分稀疏的散点，钻石之间按交错结构形成节奏，避免几十个独立“下托圆环”产生的条纹。
3. 建筑轨道镶戒：配钻嵌入戒肩表面而非直接盖在金属上，双轨连续，配钻平面与戒肩曲率协调。

做不到的项，在 PR 中继续保留未验收，而非以自动测试充数。

# 珠宝展台首次加载卡顿

2026-11-03，本地预览中复现了加载阶段的长停顿。界面先显示商品图片与“拖动旋转”，但金属预处理仍占用主线程；旧就绪回调也早于全部宝石材质和实际首帧完成。

## 测量与定位

在当前内置浏览器、标准画质、默认枕形光环模型下，通过临时 RAF 间隔记录、首次拖动记录和渲染调用计时定位。测量代码已删除；没有留在正式 UI，也没有上传数据。

| 项目 | 修改前 | 修改后 |
| --- | --- | --- |
| 加载阶段最长 RAF 间隔 | 两次复测均约 667 ms | 窄视口约 80–94 ms，1280×900 约 54 ms |
| 主线程金属遮蔽计算 | 约 529 ms | 移至 Worker |
| 主线程戒托空间索引准备 | 约 130 ms | 移至 Worker；主线程还原约 3 ms |
| 标记就绪之后的首轮拖动 | 本次样本约 1 ms | 本次样本约 1–2 ms |

主要改善是加载时的主线程停顿，而不是把已经就绪后的 1 ms 操作再加速。RAF 间隔包含浏览器调度，拖动记录到下一次绘制机会，不是 GPU 计时或端到端输入延迟测试。上述数值来自有限次本地复测，不能作为所有设备的帧率或加载时长承诺。

## 最终修改

- Worker 使用原有 SAH 空间索引与每顶点 6 次、半径 0.14 的遮蔽计算。主线程只移交几何副本，还原结果与 GPU 数据，避免把显示几何的缓冲区转移失效。
- 按已加载的源模型缓存完成的 CPU 结果；重新打开同一款可复用。切走时终止未完成的任务，取消结果不会覆盖新款式。
- 非替换主石的款式不再加载无用圆钻。经典光环所需的戒指与替换主石并行加载，重试清理相应的组合缓存。
- 等所有宝石材质准备完成，并且实际渲染器完成一帧，再启用旋转、视角与商品图输出。使用当前后处理管线的真实帧，不另外编译不同的渲染变体。
- 加载期间明确说明静态图片与三维就绪的区别；画布按需绘制，自动旋转在就绪后才持续渲染。

没有改变模型精度、折射次数、DPR、环境光、阴影采样或金属遮蔽精度。Worker 增加一个约 167 kB（未压缩）的独立脚本，首次准备仍然需要时间，但不会再把全部预处理压在页面主线程上。

## 验证

- 回归测试先复现 ProductRing 在页面线程直接执行空间索引/遮蔽计算，修改后通过。
- Worker 数据传递前后，测试几何的遮蔽数组逐项一致，空间命中距离一致；显示几何未被转移失效。
- 覆盖完成结果复用、取消任务、真正绘制前不声明就绪，以及旧款式的延迟回调不解锁新款式。
- 全部 83 项测试、已有切孔与 256 组 FORME 边界检查通过，生产构建通过。
- 浏览器检查默认款拖动、三种成品款式、宝石库、结构 DIY 和高画质切换；无新增控制台错误。

未在 OPPO Find X8 / iPhone 17 真机复测，也没有测量冷网络下载速度或长期 GPU 帧率。本轮未部署。

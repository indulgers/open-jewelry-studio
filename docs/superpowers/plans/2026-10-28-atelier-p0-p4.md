# Atelier P0–P4 Implementation Plan

> Execution: implement inline with focused parallel asset/shader work, then a fresh review. The user explicitly authorized completing P0–P4 after inspection; no further design approval is needed.

**Goal:** A complete, inspectable jewelry sample using the supplied Rhino gemstones, with calibrated lighting, local metal occlusion, improved bounded gemstone transport, and usable product-image output.

**Architecture:** Preserve React/R3F/Three WebGL and the existing procedural mode. Introduce a licensed MIT complete ring with the user's round center stone, a separate 19-shape loose-stone library, two coherent studio presets, and four repeatable camera views. Geometry and material ownership are explicit; scene-refraction queries use a shared static world-space metal BVH.

**Spec:** User-approved P0–P4 in this conversation; detailed prior comparison is `../research/2026-10-26-commercial-jewelry-comparison.md` relative to the repository parent.

## Constraints and decisions

- Keep the current visual identity and keyboard/mobile controls. The ring remains the focus.
- No proprietary WebGi SDK or CC BY-NC-ND assets copied into the application.
- 19 Rhino meshes have uncalibrated units. Display scales are explicitly illustrative; no carat/production fit claims.
- Non-round stones preview independently; do not force arbitrary shapes into an incompatible fixed round setting.
- Preserve original files and loader-cached geometry. New display geometry is cloned and disposed by its owner.
- Work in the existing preview checkout on `feat/atelier-jewelry`, preserving the user's established project path; no remote publication is part of this task.
- TAA remains static antialias accumulation, not full scene path tracing. Bounded optical transport and mount shading are documented approximations.

## Review focus

Switching shapes / modes / quality repeatedly must not dispose cached source geometry or leak BVH targets. Changes in lighting/material must reset static accumulation and invalidate generated imagery. Product-image capture must restore camera and survive interruption. Image-only display and WebGL failure must remain usable with correctly labeled preset previews. The six-prong ring accepts only the round stone; library shapes remain standalone.

## Tasks

- [ ] P0 — Copy verified display assets and attribution. Implement `prepareProductRing(scene, replacement)` with uniform round-girdle alignment; implement loose-gem normalization preserving aspect ratio. Add geometry ownership / shape / transform tests, plus four repeatable camera presets.
- [ ] P1 — Implement `StudioPresetId`, coherent metal/gem environment rotation/intensity/exposure, calibrated original light cards, controlled floor reflection, and preset controls. Adjust material uniforms without rebuilding mesh/BVH.
- [ ] P2 — Bake small-radius metal self-occlusion from the static metal BVH into a custom attribute; apply it to indirect lighting only, leaving gemstone brightness independent. Validate values and browser shading.
- [ ] P3 — Replace implicit path escape with bounded Fresnel throughput, explicit termination, consistent dispersion between quality tiers, and optional real mounted-metal intersection after gem exit. Validate optical math, resource ownership, and actual WebGL shader compilation.
- [ ] P4 — Add four-view capture with progress and downloadable product images, image-only preview, static preset fallback images and lazy viewer loading. Mark real-time exports as rendered previews, not offline path-traced photographs. Verify desktop/mobile interactions, error recovery, full tests and production build.
- [ ] Final — Independent review, fix actionable defects, record evidence and precise remaining limits in TEST-REPORT / README.
